# NarrativeIQ Public Deployment Boundaries

## Safe Public Surface

The public deployment branch is `public/demo/safe-public-niq`. It is intended for Cloudflare Pages and public GitHub exposure.

Public routes:

- `/`
- `/demo`
- `/demo/healthcare-cognition`

Public assets:

- `public/favicon.svg`
- `public/robots.txt`
- `public/sitemap.xml`
- Built Vite assets generated by the public build command

Public copy may describe NarrativeIQ as longitudinal cognition infrastructure and may show the Healthcare Cognition Lab as a public-safe product preview. Healthcare preview content must use demo data, representative categories, public-safe diagrams, and high-level investor narrative.

## Internal-Only Surface

These routes and implementation areas stay internal and must not be published to the public GitHub remote or exposed through Cloudflare Pages:

- `/modules/*`
- `/modules/new-patient-story`
- `/modules/healthcare-cognition`
- `/beta/*`
- `/app/*`
- `/lab/*`
- internal dashboards
- internal ideation boards
- ontology internals
- relation taxonomies
- scoring logic
- routing policies
- prompt logic
- embeddings strategy
- implementation documentation

## Protection Strategy

The normal internal app still uses `src/App.tsx`.

The public deployment build uses `src/PublicDeploymentApp.tsx`, selected by:

```bash
VITE_PUBLIC_DEPLOYMENT=true
```

`src/main.tsx` dynamically imports either the internal app or the public deployment app. In public deployment mode, only the public demo app is imported. Internal route modules, internal pages, module boards, beta pages, and app dashboards are not mounted by the public route registry.

The public route registry allows only:

- `/`
- `/demo`
- `/demo/healthcare-cognition`

Unknown or internal paths render a public boundary page instead of the internal app.

## SEO Boundaries

`public/sitemap.xml` must include only public-safe routes. It must not include `/modules`, `/beta`, `/app`, or internal routes.

`public/robots.txt` disallows internal route families. Robots rules are not treated as security controls; the public build boundary is the primary protection.

## Publish Workflow

Use this sequence before updating `public/demo/safe-public-niq`:

1. Validate source:

   ```bash
   npm run lint
   npm run test
   npm run build
   git diff --check
   ```

2. Validate public build:

   ```bash
   npm run validate:public
   ```

3. Verify route behavior locally:

   ```bash
   npm run build:public
   npm run preview
   curl -I http://127.0.0.1:5184/
   curl -I http://127.0.0.1:5184/demo
   curl -I http://127.0.0.1:5184/demo/healthcare-cognition
   curl -I http://127.0.0.1:5184/modules/new-patient-story
   curl -I http://127.0.0.1:5184/modules/healthcare-cognition
   ```

4. Confirm the public build audit passes:

   ```bash
   node scripts/audit-public-build.mjs
   ```

5. Update the public branch manually only after validation:

   ```bash
   git checkout public/demo/safe-public-niq
   git merge --no-ff prep/public-demo-protection-pass
   npm run validate:public
   ```

6. Push manually only after review:

   ```bash
   git push public public/demo/safe-public-niq
   ```

Do not push from automation during pre-publish validation.

## Cloudflare Pages Guidance

Cloudflare Pages should build the public branch with:

```bash
npm ci
npm run build:public
```

Build output directory:

```bash
dist
```

Environment:

```bash
VITE_PUBLIC_DEPLOYMENT=true
```

Cloudflare Pages must point at `public/demo/safe-public-niq`, not `main`, `restore/*`, `feature/*`, or `fix/*`.

## Safety Checklist

Before publishing, confirm:

- no PHI
- no diagnosis claims
- no treatment recommendations
- no clinical deployment claims
- no internal ontology/schema dumps
- no prompt logic
- no routing policy internals
- no scoring formulas
- no internal module docs
- no tracked `node_modules`, `dist`, `.vite`, `.next`, `.env`, secret, token, or key files
